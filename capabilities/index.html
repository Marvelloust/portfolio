Build modes / how the work changes shape

I do not use one process for every problem.

The same Build Record can begin as a product flow, an implementation problem, a system constraint or a production fix. The method changes with the job.

01 / FRAMEMake the product job explicit.

Clarify who is acting, what must happen and which states are actually required.

02 / MODELFind the rules underneath the screen.

Bookings, approvals, payments, files and incidents each have constraints that the interface must represent.

03 / BUILDConnect surface to system.

Implement the interface, application logic, data and external integrations as one working record.

04 / VERIFYInspect the unhappy paths.

Empty, loading, repeated, failed and permission-limited states are treated as product states, not edge decoration.

05 / FILELeave evidence behind.

Source, screenshots, implementation notes and ownership context make the work inspectable later.
